# コメント規約 (mirs_esp_pio)

AI・第三者が文脈なしで読めることを目的とする。対象は `include/` `lib/` `src/` の C++ コード。

## 1. timeless原則

- コード内コメントに来歴・議論の経緯を書かない（例：「旧propoと同一式」「〜のため振動する」は不可）。
- 来歴はコミット文・PR・`docs/adr/` に書く。コードには現在の仕様だけ残す。
- 数値の根拠は式で書く（例：`Kd*Δerr/dt`）。人名・日付・バージョンを書かない。

## 2. Doxygen軽量形（公開ヘッダのみ）

- 対象：`lib/*/Xxx.hpp` のクラス・構造体・公開メンバ関数。
- 必須タグは `@brief` `@param` `@return` のみ。`@author` `@date` `@version` は使わない。
- クラス直上に1行 `@brief` を置く。`//` コメントでは Doxygen が拾わないため `/** */` で書く。

```cpp
/** @brief 差動二輪のインターフェース層。カウント差分→左右移動距離に変換する。 */
class DiffDrive {
public:
    /**
     * @brief PID制御計算を実行
     * @param setpoint 目標値
     * @param measured 現在値（測定値）
     * @param dt_sec 制御周期 [s]
     * @return 制御出力（範囲制限済み）
     */
    double compute(double setpoint, double measured, double dt_sec);
```

## 3. 通常コメント（.cpp・非公開部）

- 書くのは意図・単位・契約の3点：なぜこうするか、単位、前提条件（範囲・周期・凍結条件）。
- 物理量には必ず単位を付ける（例：`[m/s]` `[s]` `[us]`）。
- マジックナンバー禁止。命名か `constexpr` で意味を持たせる。

## 4. 禁止事項

- コメントアウトされたコードの放置（不要なら削除し、復元はgitに任せる）。
- 自明な内容の繰返し（例：`// カウンタを増やす` のようなコードの朗読）。
- 対話・チャットの文脈を前提にした表現（例：「さっきの」「あの問題」）。

## 5. 用語集（正規名称で統一）

| 正規名称 | 意味 | 旧称・別称（使わない） |
|---|---|---|
| dt正規化PID | `P=Kp*err, I=Ki*Σ(err*dt), D=Kd*Δerr/dt` | 素累積式 |
| 公称周期 | dtクランプ範囲の基準周期 [s] | — |
| 条件付き積分 | 飽和を悪化させる方向の積分だけ凍結するアンチワインドアップ | — |

## 6. API文書の生成

```bash
doxygen Doxyfile
```

- 出力は `docs/generated/`（HTML＋XML）。git管理外。静的配置のみで動き、サーバ不要。
- 警告ゼロを維持する。新規公開API追加時は `@brief` `@param` `@return` を付けてからコミットする。
